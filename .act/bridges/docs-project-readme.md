# Project documentation

What lives in `docs/project/`: the documentation of this project as it is now, not the plan and not the
collaboration workspace (that is `docs/ai/`). Layout rules: `R-docs-order`; the check is `act-doctor`.

Keep one line here for every file and subfolder, with its state, and change it in the same step as the
file (adding, moving, finishing). A folder of five or more entries gets a `README.md` of its own in the same
shape: purpose, format, one line per entry. One topic per file; past about 300 lines it becomes a folder with
a `README.md` and parts. Numbers in file names only for a series with a reading order.

| File or folder | Contents | State |
| :--- | :--- | :--- |
| `coding_rules.md` | Which rule sets and groups are on for this stack | current |
| `glossary.md` | Terms, abbreviations and turns of phrase specific to this project | current |
